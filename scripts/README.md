# JetPack-Scripts

Automation scripts for setting up multi-machine JetPack experiments and running repeatable batches on AWS or Zoo clusters.

This repo is an orchestration layer around the main `JetPack` codebase. It handles:
- cluster inventory and `setup.json` generation
- SSH trust/bootstrap across machines
- AWS NFS setup
- remote build + experiment launch
- Docker-based local benchmark sweeps
- result collection (`.res` + `.csv` + `.tsv`)
- helper analysis scripts and notebooks

## Script classification

| Category | Scripts | Description |
|---|---|---|
| **Canonical (current)** | `sweep_benchmark.sh`, `run_full_sweep.sh`, `rerun_failed_points.sh`, `patch_canonical_with_reruns.sh`, `test_sweep_benchmark.sh` | Docker-based local benchmark and sweep pipeline |
| **Canonical (result processing)** | `build_consolidated_csv.sh`, `tsv_to_md.sh`, `calc_latency.py`, `results_reader.py` | Result parsing, conversion, and analysis |
| **Shared definitions** | `experiment_defs.sh`, `test_experiment_defs.sh` | Centralized protocol/backend/mode definitions, concurrency arrays, and command-generation helpers sourced by entry scripts |
| **Legacy (AWS/Zoo)** | `00-ips.sh` through `11-aws-copilot-property.sh`, `93-99` ops helpers | AWS/Zoo cluster setup, remote experiment runs, ops |

## Repo at a glance

- `00-11` scripts: AWS/Zoo setup + run flow (legacy cluster workflow)
- `93-99` scripts: operations helpers (restart/check/cleanup)
- `sweep_benchmark.sh`, `run_full_sweep.sh`: Docker-based local sweep pipeline (current)
- `results/`, `test_output/`, `latency_results/`: generated outputs
- `evaluation.ipynb`: plotting and post-processing notebook

## Prerequisites

### Docker-based local sweeps (current path)

- Docker with `docker compose`
- Built backend images: `jetpack-etcd`, `jetpack-mongodb`, `jetpack-zookeeper`
- See `docs/benchmark_runbook.md` for image build commands

### AWS/Zoo cluster runs (legacy path)

Run scripts from this directory on a controller machine with:
- `bash`, `ssh`, `scp`, `jq`, `timeout`, `bc`, `python3`
- network access to all experiment machines
- valid SSH access for the target environment

Cluster assumptions:
- Remote hosts are Linux (Ubuntu-style setup assumed in multiple scripts)
- `JetPack` repo path:
  - AWS: `/home/ubuntu/code/JetPack`
  - Zoo: value from `setup.json.zoo_directory`

## Config files and generated state

- `aws_ips.json`, `zoo_ips.json`: source inventories
- `setup.json`: generated by `./00-ips.sh`; consumed by almost every legacy script

`setup.json` is the control-plane state for the legacy scripts. Re-run `./00-ips.sh` whenever you switch between AWS and Zoo.

## Docker-based sweep pipeline (current)

### `sweep_benchmark.sh`

Run a concurrency sweep for a given backend/mode combination using Docker.

Usage:
```bash
./sweep_benchmark.sh <docker_image> <mode_config> [extra_server_args]
```

Examples:
```bash
./sweep_benchmark.sh jetpack-etcd none_etcd.yml
./sweep_benchmark.sh jetpack-etcd rule_etcd.yml "-m 100"
./sweep_benchmark.sh jetpack-mongodb none_mongodb.yml
```

Output: TSV with columns for concurrency, throughput per host, fast-path metrics, CPU/queue stats, status, and retry count.

### `run_full_sweep.sh`

Run all 9 backend/mode sweeps and regenerate canonical artifacts.

Usage:
```bash
./scripts/run_full_sweep.sh          # run all 9 cases
./scripts/run_full_sweep.sh etcd     # run only etcd cases (3 modes)
```

The 9 cases are:
- etcd: original / fastpath100 / adaptive
- MongoDB: original / fastpath100 / adaptive
- ZooKeeper: original / fastpath100 / adaptive

Results are saved as canonical TSV files under `docs/sweep_2026-02-28/`.

### `rerun_failed_points.sh`

Rerun only specific failed concurrency points from a previous sweep. Uses the same retry/classification logic as `sweep_benchmark.sh`.

### `patch_canonical_with_reruns.sh`

Update canonical TSV files with successful rerun data, replacing zero-throughput rows.

### `test_sweep_benchmark.sh`

Unit tests for `sweep_benchmark.sh` — tests failure handling, retry logic, status classification, and output format by mocking the docker command.

```bash
bash scripts/test_sweep_benchmark.sh
```

## Legacy AWS/Zoo run scripts

### Quick start (machines already provisioned)

1. Create/refresh cluster config:
```bash
./00-ips.sh
```
2. Prepare SSH trust:
```bash
./01-exchange_keys.sh
```
3. AWS only, if first run or after reboot:
```bash
./04-nfs.sh
./95-restart_mongodb.sh   # optional, only for the 5 MongoDB nodes
```
4. Run WAN experiment:
```bash
./09-build_and_test_run_wan.sh
```

Useful variants:
```bash
# Rebuild before running
./09-build_and_test_run_wan.sh build

# Full regen + build before running
./09-build_and_test_run_wan.sh full

# Failure recovery mode
./09-build_and_test_run_wan.sh -F --filename jetpack-failure-recovery

# Dry-run: print commands without executing (no SSH needed)
./09-build_and_test_run_wan.sh --dry-run
./09-build_and_test_run_wan.sh --dry-run --failover build
./10-run_all.sh --dry-run
```

### Full AWS bootstrap (fresh machines)

Run in this order:

1. `./00-ips.sh`
2. `./01-exchange_keys.sh`
3. `./02-setup.sh`
4. `./04-nfs.sh`
5. `./05-clone_repo_and_set_default_folder.sh`
6. `./06-set_jetpack_env.sh`
7. `./07-link_mongocxx.sh`
8. `./09-build_and_test_run_wan.sh build`

Notes:
- `02-setup.sh` pushes and runs `aws_setup_script.sh` on all nodes.
- `05` prints server0's SSH public key and pauses until you add it to GitHub, then clones `JetPack` and configures shell aliases/default directory.
- `04` makes server0 the NFS host and mounts `/home/ubuntu/code` on other AWS nodes.

### `08-build_and_test_run_local.sh`

Single sanity run using fixed config files in the script.

Usage:
```bash
./08-build_and_test_run_local.sh [full|build]
```

Outputs:
- `test_output/output_server*.txt`

### `09-build_and_test_run_wan.sh`

Primary WAN experiment runner.

Usage:
```bash
./09-build_and_test_run_wan.sh [full|build] [--failover|-F] [--filename|-o <prefix>]
```

Behavior:
- derives server list from `setup.json`
- builds `deptran_server` command from config constants near top of script
- runs one process per server with a 180s timeout
- writes local `.res` files to `test_output/`
- pulls matching CSVs from `results/recent_csv` on server0
- auto-runs `98-kill.sh` if any run timed out

### `10-run_all.sh`

Large batch sweeps over protocols/workloads/concurrency.

Usage:
```bash
./10-run_all.sh [full|build]
```

Behavior summary:
- create experiment dir: `results/<timestamp>-<git_hash>`
- execute all generated configs from arrays in script
- retry failed configs in loops until no failures remain
- mark failures on missing markers, oversized `.res` (>50 MiB), missing files, or very low throughput
- copy `.res`, `.csv`, and `tdigest_*.csv` back to local experiment dir

Before running, edit arrays in the script (`jetpack_protocols`, `origin_protocols`, `workloads`, `zipf_workloads`, `key_range_workloads`, concurrency sets, etc.) to match your target matrix.

### `11-aws-copilot-property.sh`

Targeted comparison runner for `none/rule100/rule101` Copilot experiments.

Usage:
```bash
./11-aws-copilot-property.sh [full|build] [none|rule100|rule101|all]
```

It injects temporary `tc netem delay 300ms` on server0 during the run and removes it on exit.

## Ops/helper scripts

| Script | Purpose |
|---|---|
| `03-ping.sh` | Measure local->server and inter-server ping latencies, writes JSON in `latency_results/` |
| `94-check-time-sync.sh` | Check `timedatectl` + `chronyc` across AWS nodes |
| `95-restart_mongodb.sh` | Restart MongoDB on server0, then servers1-4 (expects `n_server=10`) |
| `97-git_commit_hash.sh` | Print current commit hash on remote server0 JetPack repo |
| `98-kill.sh` | `pkill -9 -f deptran` on all nodes from `setup.json` |
| `99-append_ssh_key.sh` | Append a provided SSH public key to all nodes' `authorized_keys` |
| `96-execute.sh` | Legacy helper: execute one command on `AWS_0_IP`...`AWS_9_IP` env targets |

Note: `93-restart_etcd.sh` is referenced in some docs but does not currently exist. etcd restart is handled via Docker compose in the current workflow.

## Outputs

- `test_output/`: single-run artifacts (`.res`, pulled CSV, stdout logs)
- `results/<timestamp>-<hash>/`: batch artifacts from `10-run_all.sh`
- `results/recent_csv/` (remote JetPack repo): latest CSVs before pullback
- `latency_results/latency_results_<timestamp>.json`: output from `03-ping.sh`
- `docs/sweep_2026-02-28/`: canonical TSV files from Docker-based sweeps

There are also checked-in historical datasets, including failure-recovery folders and merged CSVs in `results/`.

## MongoDB notes (operational)

- Restart replica-set nodes used by experiments:
```bash
./95-restart_mongodb.sh
```
- For custom binary target, override `mongod` service `ExecStart` with `sudo systemctl edit mongod`.
- For fresh binary swaps, clear old data dir before re-init (`/var/lib/mongodb/*`).

## Caveats and safety notes

- Many scripts assume username/path conventions; verify constants before long runs.
- `03-ping.sh` SSH checks are effectively AWS-centric (`ubuntu@...` hardcoded in remote ping command).
- `96-execute.sh` does not use `setup.json`; it relies on exported `AWS_*` env vars.
- `aws_setup_script.sh` currently contains hardcoded git config content; review and sanitize before use in shared environments.
